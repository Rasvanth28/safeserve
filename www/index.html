1. Naive Mode (Circular Wait Freeze)

Requests acquire resources incrementally without global coordination:

Request 1: /refresh
Holds DB
Waits for CLOCK
⇄
Request 2: /upload
Holds CLOCK
Waits for DB
Consequence: Deadlock occurs. Both requests stall forever, occupying worker slots until the entire server becomes unresponsive.
2. SafeServe Banker's Mode (Zero Deadlock)

Requests submit their declared maximum claims to the admission controller:

Admission Controller
Runs Safety Check
O(n² · m) < 10 µs
➜
Safe Serialization
Grants Request 1
Request 2 waits on CV
Consequence: Zero deadlocks. Request 1 executes safely and releases resources, waking Request 2 via pthread_cond_broadcast.
How the 4 strategies work — step by step

Scenario (same for all four): 1 database connection (DB) and 1 cache lock (CLOCK). R1 = POST /refresh takes DB, then CLOCK. R2 = POST /upload takes CLOCK, then DB. Both declare a maximum claim of 1 DB + 1 CLOCK. This is the workload of make demo.
